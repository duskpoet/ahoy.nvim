1. USAGE                                                          *ahoy-usage*

                                                                       *:Ahoy*
:Ahoy           Open the dashboard in the current window. If it is already
                shown there, refresh it (re-detect context, refetch).

The dashboard opens on startup when nvim is started without file arguments
and with an empty buffer (see `show_on_startup`).

Default keys in the dashboard:
  <CR>   run the action of the row under the cursor
  o      open the row in the browser
  r      refresh
  q      return to the previous buffer

Context is detected once per open and decides the layout:
  pr      on a feature branch (`ctx.pr` is set if it has an open PR)
  main    on the default branch or detached HEAD
  global  not in a git repo

==============================================================================
2. CONFIGURATION                                                 *ahoy-config*

>lua
  require("ahoy").setup({
    show_on_startup = true,
    keymap = "<leader>a",          -- open/refresh mapping, nil for none
    idle = true,                   -- false disables the idle pool
    sections = { ... },            -- see |ahoy-sections|
    layouts = {
      main   = { header = "status", hero = "calendar",
                 cards = { "waiting", "my_prs", "latest" } },
      pr     = { header = "status", hero = "calendar",
                 cards = { "pr", "threads", "activity" } },
      global = { hero = "calendar", cards = { "waiting", "streak" } },
    },
    grid = { two_columns = 160, compact = 100, max_width = 220,
             card_max_lines = 14, hero_max_lines = 18 },
    keys = { open = "<CR>", browser = "o", refresh = "r", quit = "q" },
    browser = "auto",              -- "open" | "copy" | function(url); auto
                                   -- copies to "+" over SSH (OSC 52-friendly)
    timezone = nil,                -- "Europe/Berlin"; nil = system zone
    calendar = { url_file = "~/.config/ahoy/ics_url", email = nil,
                 day_start = 9, day_end = 18 },
    github = { limit = 30, mentions_days = 14, latest = 12,
               max_reviews = 5, hide_bots = true },
  })
<
Layouts are merged per context; each slot you set replaces the default list.
Slots: `header` (one section), `hero` (fallback list: the first section that
is loading or has data wins), `tickers` (one-line strips), `cards` (grid,
two-up when the window is at least `grid.two_columns` wide; a section with
`wide = true`, like `pr`, always takes a full row).
The calendar is the hero in every context by default.

3. SECTIONS                                                    *ahoy-sections*

>lua
  {
    name   = "my_prs",
    title  = "My PRs",                   -- or function(data|nil); default name
    wide   = false,                      -- true: card never shares a row
    slots  = { "card", "ticker" },       -- optional, defaults to all
    when   = function(ctx) return true end,
    fetch  = function(ctx, done) done(data) end,
    render = function(data, slot, width)
      return { lines = lines, highlights = hls, keymaps = keymaps }
    end,
    empty   = "nothing here",            -- text for done(nil)
    timeout = 30000,                     -- ms, false for none
  }
<
`fetch` calls `done(data)` for data, `done(nil)` for "nothing", or
`done(nil, err)` for an error. Errors thrown by fetch/render are shown in the
card. `ctx` has: cwd, time, kind, root, branch, default_branch, git, pr.

`render` returns:
  lines       list of strings, or lists of `{ text, hl_group }` chunks
  highlights  `{ row, col_start, col_end, group }` (1-based row, byte cols,
              col_end -1 = end of line)
  keymaps     `{ [row] = { ["<CR>"] = fn(ctx), o = fn(ctx) } }`

Built-in sections:
  status    header: path, branch, clean/dirty, ahead/behind, date/time
  waiting   card/ticker: review requests, unresolved threads on my PRs,
            failing CI, approved+mergeable PRs, @mentions
  my_prs    card/ticker: my open PRs with CI x/y, review state, age
  latest    card/ticker: recent activity by others on my PRs
  pr        hero/card (full row): this branch's PR — checks x/y, per-reviewer state,
            mergeability (and why it's blocked), diffstat, timeline,
            failing checks (`<CR>` = failed log). Without an open PR:
            diffstat vs base, push state, and `git push` / `gh pr create`
            commands (`<CR>` copies; ahoy never runs them)
  threads   card/ticker: unresolved review threads (● = waiting on you);
            `<CR>` jumps to file:line, `o` opens the thread
  activity  card/ticker: comments, reviews, pushes, review requests, CI
Set `sections = { status = false }` to remove a built-in.

The GitHub sections share one `gh api graphql` request per refresh (one for
the main view, one for the PR view) and need
an authenticated `gh` CLI. Row actions (`<CR>`):
  review request   `gh pr checkout` + `:Git difftool -y origin/<base>...`
  threads, my PR   `gh pr checkout` + refresh (lands in the `pr` layout)
  failing CI       `gh run view <id> --log-failed` in a split
  merge, mention   open in the browser
Checkout only happens for PRs in the current repo (else: browser), and asks
first if the working tree is dirty. `o` always opens the row in the browser.
ahoy never merges, pushes or comments.

`ctx.repo` is "owner/name" parsed from the `origin` remote.

Calendar sections:
  calendar      hero/card "Today · <date>", the default hero everywhere.
                As hero: current or next meeting with countdown and call
                link (`<CR>`), the working-day strip (━ elapsed,
                ▆ meetings, ● now), then today's agenda (past dimmed and
                collapsed once the day is long, current ▶, declined
                labelled). As card: the agenda + "fetched at". Never
                hidden: without the URL file it shows how to set it up,
                with no events "No meetings today".
  next_meeting  hero/ticker (only when the URL file exists): current or
                next meeting with countdown and what's after. Empty when
                nothing is left today, so a hero fallback list moves on.

Put your Google Calendar "Secret address in iCal format" in
`~/.config/ahoy/ics_url` and `chmod 600` it (ahoy warns otherwise). The URL
is never accepted in setup(), is handed to curl on stdin (not visible in
`ps`), and is never displayed. Supported recurrence: DAILY/WEEKLY/MONTHLY/
YEARLY with INTERVAL, BYDAY (incl. 2TU / -1FR), BYMONTHDAY, BYMONTH, WKST,
UNTIL, COUNT, EXDATE, RDATE, RECURRENCE-ID overrides and TZID (system
zoneinfo). Anything else is shown with ⚠. Declined = PARTSTAT=DECLINED for
`calendar.email` (default: the calendar name if it is an email).
Countdowns re-render every minute without refetching.
